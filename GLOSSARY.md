# Glossary

Terms as harnessd uses them. Use them as written here in issues, tests and docs.

**Default skill pack**: the skills every harnessd user gets from `harnessd init` (D-016, D-020). The list is in `.claude/skills/VENDORED.md` and `packages/cli/src/pack.ts`.

**Pin**: the `commit` in a `[skills.<name>]` table of `~/.harnessd/config.toml`. init installs a default skill only at its pin. _Avoid_: version lock.

**Pack marker**: the `.harnessd-pack` file in a skill folder that init installed. A folder without it belongs to the user.

**Native folder**: the `.harnessd-native/` folder in a skill. It holds the skill's hooks (`hooks.json`) and Claude Code subagents (`claude-agents/`). Sync merges them into the harness files; it does not copy the folder (D-028).

**Subagent**: a harness's own agent file, such as `.claude/agents/impeccable-finish-reviewer.md`. It is not a harnessd agent (coordinator, backend, frontend, qa). _Avoid_: agent, when you mean a subagent.

**Generated note**: the "Generated by `harnessd sync`" line in a file that sync wrote. A skill folder whose SKILL.md has no generated note belongs to the user, and sync does not write into it. The same holds for a subagent file.

**Notice**: one line to the owner about one event, a merge or a block. It links the issue, and the PR when there is one (D-015, D-021). _Avoid_: ping, alert, notification.

**Block**: work that stops until a human acts: Needs input, an escalation, two QA or gate failures, or a protected PR that waits for a human. _Avoid_: blocker, failure.

**Daily summary**: one message a day, at the summary time, that lists the merges and blocks since the last daily summary and the work in progress. _Avoid_: digest, report, recap.

**Workspace glossary**: the term notes in `<repo>/.harnessd/vault/glossary/`. The coordinator grill writes new terms there. _Avoid_: vault glossary file.

**Draft decision record**: a decision record that the grill wrote to `<repo>/.harnessd/vault/decision-drafts/`, numbered `D-NNN` until a docs PR accepts it. _Avoid_: proposed ADR.

**Precedent**: a call that is hard to reverse, surprising without context and the result of a real trade-off. Each precedent becomes a draft decision record.

**Status engine**: the one source of checks for `harnessd doctor`, the start of `harnessd run` and the app (D-023).

**Check**: one line of `harnessd doctor`: an id, a state, a detail and a fix (D-023). _Avoid_: probe, health check.

**Blocking check**: a check in state `fail` or `missing`. `harnessd run` does not start while one exists.

**Board**: the issues of the team and project, grouped by workflow state. Done shows the last 7 days. Canceled issues are left out.

**Needs you**: the board column for issues a human must act on. It holds issues in **Needs input** and **Blocked** issues. It is the loudest thing in the UI (PRODUCT.md).

**Needs input**: the Linear workflow state for an issue the coordinator escalated (D-011), or one that failed twice (D-014).

**Blocked**: an issue whose PR waits for a human at the merge gate (D-013), for example because it touches a protected path. An issue that only waits for another issue is not Blocked; it shows its blockers.

**Budget used**: elapsed wall-clock time of a run over its size budget (S 30 min, M 2 h, D-014).

**Run**: one agent working one sub-issue in its own worktree (D-012). A QA round is one run.

**Event stream**: the server-sent events at `GET /api/events` that push pause, board, agent and log changes to the UI (D-024).

**Held update**: a live change the UI keeps back while the pointer or focus is in that region, so content never moves under the cursor.

**Command palette**: the dialog that Cmd+K (Ctrl+K) opens. It lists every action in the app and runs the one you pick (D-025). _Avoid_: command menu, quick open.

**Optimistic pause**: the pause control shows the new state on the click, before the daemon answers, and rolls back if the call fails (DESIGN.md).

**Setup**: the state of `harnessd run` when the app is served but the loop has not started, because a check blocks or Start was not pressed (D-026). _Avoid_: onboarding mode, idle.

**Setup command**: one fixed command the app runs for a harness: install, update or sign in. Nothing from the request reaches it (D-026). _Avoid_: script, action.

**Login prompt**: the first `https://` URL and device code that a harness CLI's sign-in prints, kept on the job as `url` and `code` for the app to show (D-031). _Avoid_: auth link, OTP.

**Secret store**: the folder `~/.harnessd/secrets/`, one owner-only file per secret, with fixed ids such as `linear.api_key` (D-030). _Avoid_: vault (the vault is memory), keychain.

**Secret reference**: an `op://vault/item/field` or `env:NAME` string that stands for a secret. Config holds the reference, never the value. _Avoid_: secret path.

**Secret source**: where the lookup found a secret: `saved`, `1Password` or `env`. The status engine and the app show the source, never the value. _Avoid_: origin, provider.

**Service logo**: the one-color logo of a service harnessd works with (GitHub, Linear, Slack, Claude, OpenAI, git), always next to its name (D-029). _Avoid_: brand icon, provider icon.

**Brand token**: the `--brand` line in `index.css` that holds the accent for light and dark. Primary and ring read it (D-029). _Avoid_: theme color.

**Failure reason**: the `reason` of a run that ended in `error` because the human must act outside the run: `usage_limit` (the harness quota is spent) or `auth` (the harness is not signed in). Other errors have no failure reason. _Avoid_: error type, error code.

**Self-update**: harnessd pulls, rebuilds and restarts its own install after a merge to its own repo's default branch (MET-63, docs/LOOP.md "Self-update"). _Avoid_: auto-upgrade, `harnessd update` (that updates a harness CLI).

**Safe point**: the first tick with no run in flight while a self-update waits. Only then is the update applied. _Avoid_: idle point.

**Trigger issue**: the parent issue whose merge started a self-update check. A blocked or failed update comments on it and moves it to Needs input. The check at daemon start has none.
