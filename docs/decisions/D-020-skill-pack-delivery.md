# D-020 The skill pack ships in the CLI; sync owns only what it generated
Status: draft 2026-11-20. Extends D-016. `@harnessd/cli` holds the default skill pack, copied from `.claude/skills/` at build time into `dist/pack/`. So `harnessd init` needs no network, and the pin is the package version plus the commits in VENDORED.md. init writes a `[skills.<name>]` pin for each new skill and changes a skill folder only when its pin names the shipped commit. A workspace turns a skill off with `enabled = false`. Sync copies the whole skill folder and keeps all frontmatter, to `.claude/skills/` (Claude Code) and `.agents/skills/` (Codex). Sync never writes into a skill folder whose SKILL.md lacks the generated note. Why: no network at init, an upgrade never changes agents without a config change, and a repo with hand-vendored skills (this repo, MET-20) stays safe. Issue: MET-21.
