# harnessd sync

`harnessd sync [dir]` turns the merged config (docs/CONFIG.md) into the files each harness reads natively, in `dir` (default: the current directory). It reads `$HARNESSD_HOME` (default `~/.harnessd`) and `<dir>/.harnessd/`; it never writes to the global folder. The repo must have a `.harnessd/` folder (it may be empty), so sync never takes over a hand-written AGENTS.md by accident.

| File | Harness | From |
|---|---|---|
| `AGENTS.md` | all; Codex reads it natively | global AGENTS.md, workspace AGENTS.md, then `## Rules` (merged rules by name) |
| `CLAUDE.md` | Claude Code | symlink to `AGENTS.md` (D-004) |
| `.claude/settings.json` | Claude Code | `enabledMcpjsonServers`: every MCP server name, plus the skills' hooks. Merged, not replaced (see "Hooks and subagents") |
| `.claude/agents/<name>.md` | Claude Code | the Claude Code subagents that enabled skills ship |
| `.claude/skills/<name>/` | Claude Code | each merged, enabled skill: SKILL.md and every other file in its folder |
| `.agents/skills/<name>/` | Codex | the same skills. OpenCode 2.x reads `.claude/skills/` and `.agents/skills/`, so it gets no folder of its own |
| `.mcp.json` | Claude Code | `[mcp.<name>]` tables plus `harnessd-memory` |
| `.codex/config.toml` | Codex | the same servers as `[mcp_servers.<name>]` |
| `.codex/hooks.json` | Codex | the skills' Codex hooks; only when a skill has some. Merged, not replaced |
| `opencode.json` | OpenCode | the same servers as local `mcp` entries. Merged, not replaced: sync owns `$schema`, `permission`, `websearch` and its own `mcp` entries by name |

Every repo gets the built-in memory server (docs/MEMORY.md) as `harnessd-memory`, run as `harnessd mcp memory`. To run it another way (say `npx -y @harnessd/cli mcp memory` when `harnessd` is not on PATH), define `[mcp.harnessd-memory]` yourself; it replaces the default.

Agent-specific instructions are not written to AGENTS.md; adapters pass them per run.

The loop runs the same sync into each worktree before an agent run (docs/LOOP.md "What an agent run sees").

## Skills
Sync writes every merged skill that is not turned off (docs/CONFIG.md "Skills"). This includes the default skill pack that `harnessd init` installs in `~/.harnessd/skills/`.
- SKILL.md gets `name`, `description`, the other frontmatter lines as they are, the generated note, then the body.
- Sync copies every other file byte for byte, with its executable bit. Sync does not copy the `.harnessd-pack` marker.
- Sync writes into a skill folder only when the folder is absent or its SKILL.md has the generated note after the frontmatter. It never writes into, or deletes, any other folder. Sync prints `kept <folder>: not generated by harnessd sync` for each one. So a repo can keep its own hand-vendored skills, such as this repo's `.claude/skills/`.
- To let sync own such a folder, delete it and run sync again.
- Sync never deletes. After you turn a skill off, delete its folders in `.claude/skills/` and `.agents/skills/` by hand.

## Hooks and subagents
A skill can ship harness files in a `.harnessd-native/` folder. Sync does not copy that folder into the skill folders.
- `.harnessd-native/hooks.json`: `{ "claude": {...}, "codex": {...} }`. Each value is a `hooks` table: event name to matcher groups, as in `.claude/settings.json`.
- `.harnessd-native/claude-agents/<name>.md`: Claude Code subagents.

In the default skill pack, impeccable has both (D-028):
- Claude Code hooks: `SessionStart`, `PostToolUse` on `Edit|Write` and `Stop`. Each runs `.claude/skills/impeccable/scripts/impeccable hook`.
- Codex hooks: `PostToolUse` on `Edit|Write|apply_patch` and `Stop`. Each runs `.agents/skills/impeccable/scripts/impeccable hook`. Codex asks you to approve the hook in `/hooks` the first time.
- Subagents: `impeccable-finish-reviewer`, `impeccable-motion-reviewer`, `impeccable-documenter`, `impeccable-asset-producer` and `impeccable-manual-edit-applier`.

A skill that is turned off (`[skills.impeccable] enabled = false`) gives no hooks and no subagents.

**Merge.** Sync merges into `.claude/settings.json` and `.codex/hooks.json`. It does not replace them.
- Sync sets `$schema` and `enabledMcpjsonServers`. A key that exists keeps its place.
- Sync keeps every other key, such as `permissions`, `env` or `description`.
- For each skill hook group, sync looks for a group with the same matcher and a shared command. It replaces that group in place. Otherwise it appends the group to the event.
- Sync keeps every other hook group.
- So a second run gives the same bytes. A repo that already has the hook, such as this repo, keeps it unchanged.
- A file that is not a JSON object stops sync, and sync writes nothing. Fix or delete the file.
- Sync never deletes a hook or a subagent file. After you turn a skill off, delete them by hand. A later pin that changes a hook's command or matcher adds a new group; delete the old one by hand.

**Subagents.** Sync writes `.claude/agents/<name>.md` with the generated note after the frontmatter. It writes a subagent file only when the file is absent or has the generated note. It prints `kept .claude/agents/<name>.md: not generated by harnessd sync` for any other file. Subagent files that no skill ships are never touched.

`harnessd doctor` checks the hooks. The `skills.pack` check is `warn` when an enabled skill's Claude Code hook is missing from `.claude/settings.json`. The fix is `Run: harnessd sync`.

Sync writes a file only when its content (or link target) differs and prints the paths it wrote, or `no changes`. Generated files start with a "Generated by `harnessd sync`" note where the format allows comments; edit `.harnessd/` instead. Files sync no longer generates (a removed skill, say) are left in place; delete them by hand.

## What to commit
Commit `.harnessd/` (including `vault/`, the repo's shared memory), `AGENTS.md`, `CLAUDE.md`, `.claude/settings.json`, `.claude/agents/`, `.claude/skills/` and `.agents/skills/`. `.codex/hooks.json` is in `.codex/`, so it is not committed; each machine gets it from sync. Ignore the MCP files, since `env` values may hold tokens and commands may be machine-specific:

```gitignore
.mcp.json
.codex/
opencode.json
```

**opencode.json.** Sync merges into it. It replaces `$schema`, `permission` and `websearch` as whole keys. It sets one `mcp` entry for each of its servers, by name. User-owned `mcp` entries and keys such as `model` and `provider` stay. Owner sync writes the default permission table. Worktree sync applies the run agent's `opencode_permission` overrides. Sync sets the Web Search provider to `random`. A file that is not a JSON object, or whose `mcp` is not an object, stops sync.

Global AGENTS.md and rules end up in the repo's AGENTS.md, so keep anything private out of `~/.harnessd/`.

## Tests
Golden cases live in `packages/daemon/test/fixtures/sync/<case>/` (`global/`, `workspace/`, `expected/`). After an intended output change, regenerate with `UPDATE_GOLDEN=1 node --test src/sync/sync.test.ts` in `packages/daemon` (build first) and review the diff.
