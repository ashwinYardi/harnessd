# harnessd sync

`harnessd sync [dir]` turns the merged config (docs/CONFIG.md) into the files each harness reads natively, in `dir` (default: the current directory). It reads `$HARNESSD_HOME` (default `~/.harnessd`) and `<dir>/.harnessd/`; it never writes to the global folder. The repo must have a `.harnessd/` folder (it may be empty), so sync never takes over a hand-written AGENTS.md by accident.

| File | Harness | From |
|---|---|---|
| `AGENTS.md` | all; Codex reads it natively | global AGENTS.md, workspace AGENTS.md, then `## Rules` (merged rules by name) |
| `CLAUDE.md` | Claude Code | symlink to `AGENTS.md` (D-004) |
| `.claude/settings.json` | Claude Code | `enabledMcpjsonServers`: every MCP server name |
| `.claude/skills/<name>/` | Claude Code | each merged, enabled skill: SKILL.md and every other file in its folder |
| `.agents/skills/<name>/` | Codex | the same skills |
| `.mcp.json` | Claude Code | `[mcp.<name>]` tables plus `harnessd-memory` |
| `.codex/config.toml` | Codex | the same servers as `[mcp_servers.<name>]` |

Every repo gets the built-in memory server (docs/MEMORY.md) as `harnessd-memory`, run as `harnessd mcp memory`. To run it another way (say `npx -y @harnessd/cli mcp memory` when `harnessd` is not on PATH), define `[mcp.harnessd-memory]` yourself; it replaces the default.

Agent-specific instructions are not written to AGENTS.md; adapters pass them per run.

## Skills
Sync writes every merged skill that is not turned off (docs/CONFIG.md "Skills"). This includes the default skill pack that `harnessd init` installs in `~/.harnessd/skills/`.
- SKILL.md gets `name`, `description`, the other frontmatter lines as they are, the generated note, then the body.
- Every other file is copied byte for byte, with its executable bit. The `.harnessd-pack` marker is not copied.
- Sync writes into a skill folder only when the folder is absent or its SKILL.md has the generated note. It never writes into, or deletes, any other folder. Sync prints `kept <folder>: not generated by harnessd sync` for each one. So a repo can keep its own hand-vendored skills, such as this repo's `.claude/skills/`.
- To let sync own such a folder, delete it and run sync again.

Sync writes a file only when its content (or link target) differs and prints the paths it wrote, or `no changes`. Generated files start with a "Generated by `harnessd sync`" note where the format allows comments; edit `.harnessd/` instead. Files sync no longer generates (a removed skill, say) are left in place; delete them by hand.

## What to commit
Commit `.harnessd/` (including `vault/`, the repo's shared memory), `AGENTS.md`, `CLAUDE.md`, `.claude/settings.json`, `.claude/skills/` and `.agents/skills/`. Ignore the MCP files, since `env` values may hold tokens and commands may be machine-specific:

```gitignore
.mcp.json
.codex/
```

Global AGENTS.md and rules end up in the repo's AGENTS.md, so keep anything private out of `~/.harnessd/`.

## Tests
Golden cases live in `packages/daemon/test/fixtures/sync/<case>/` (`global/`, `workspace/`, `expected/`). After an intended output change, regenerate with `UPDATE_GOLDEN=1 node --test src/sync/sync.test.ts` in `packages/daemon` (build first) and review the diff.
